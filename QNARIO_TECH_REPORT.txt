QNARIO PROJECT: TECHNICAL CORE STACK REPORT
==========================================

1. FRONTEND: THE USER INTERFACE & EXPERIENCE
------------------------------------------
The "Qnario" frontend is designed to be lightweight, fast, and visually premium, focusing on the teacher and student dashboards.

* HTML5, CSS3, & JavaScript (ES6+):
  - Usage: Used across 30+ pages (e.g., teacher-dashboard.html, student-exam.html).
  - Role: HTML handles the structure of the exam portals, while JavaScript manages the logic for timer countdowns and dynamic question rendering.

* Vanilla CSS (Custom UI & Responsive Design):
  - Usage: Consistently applied via styles-global.css.
  - Role: Creates a "Glassmorphism" aesthetic with dark-themed cards and smooth transitions.

* Cursor Ripple Effect (Interactive UX):
  - Usage: Implemented in cursor-ripple.js for landing and login pages.
  - Role: Provides a high-end interactive feel by creating visual waves that follow the user's mouse pointer.

* Axios (Networking):
  - Usage: Found in frontend scripts for syllabus uploads and exam submissions.
  - Role: Handles communication between the browser and the Node.js API without reloading the page.

* Socket.io-client (Real-time Interaction):
  - Usage: Integrated into the "Live Exam Room" pages.
  - Role: Allows students to receive "Exam Started" signals and sends progress to the teacher instantly.


2. BACKEND: DUAL-SERVER MICROSERVICE ARCHITECTURE
------------------------------------------------
Qnario uses a modern microservices approach to separate general management from AI-heavy tasks.

* Primary Server (Node.js & Express.js):
  - Usage: The main server.js file and the qnario/ directory.
  - Role: The "Command Center." It manages user roles, handles routing, and bridges the database/frontend.

* AI Microservice (Python 3.10 & Flask):
  - Usage: Located in the gemini-microservice/ folder.
  - Role: A dedicated engine that receives raw text, communicates with Google Gemini, and returns structured JSON.

* Socket.io (Server-Side Communication):
  - Usage: Configured in server.js to manage room namespaces.
  - Role: Maintains a live connection for students, allowing teachers to see a "Live Monitor" of progress.

* Security (BcryptJS & JWT):
  - Usage: Applied in auth-utility scripts and login routes.
  - Role: Bcrypt hashes passwords for safety, while JWT ensures secure student-only access to exams.


3. ARTIFICIAL INTELLIGENCE: THE GEMINI ENGINE
--------------------------------------------
The core intelligence of Qnario relies on Google’s advanced models to automate educational content creation.

* Google Gemini 1.5 Flash / Pro:
  - Usage: Integrated via API keys in both servers.
  - Role: Understands complex syllabus hierarchies (Units vs. Chapters).

* Automated Syllabus Parsing:
  - Role: Scans uploaded PDFs to extract clean lists of topics, saved to syllabi.json.

* Dynamic Question Generation:
  - Role: Generates high-quality MCQs and descriptive questions based on Bloom's Taxonomy.

* Performance Insights:
  - Role: Analyzes score patterns to identify "Weak Topics" and generate study recommendations.


4. DATABASE & STORAGE LAYER
---------------------------
Qnario uses a "Dual-Storage" strategy for maximum reliability.

* MongoDB (Mongoose ODM):
  - Usage: Defined in models/ (e.g., Question.js, StudentResult.js).
  - Role: Formal database for complex student records, grades, and historical analytics.

* JSON-Based Local Storage:
  - Usage: Files like users.json and syllabus-papers.json.
  - Role: High-speed cache and fallback system for when MongoDB is offline.

* Multer (File Storage):
  - Usage: Middleware in the syllabus upload route.
  - Role: Securely stores uploaded PDFs and images in the /uploads/syllabi folder.


5. UTILITIES & FILE PROCESSING
------------------------------
* PDF-Parse: Converts raw PDF data into text that the Gemini model can read.
* Mammoth (DOCX Parsing): Handles Word documents, preserving structure for the AI.
* Dotenv: Protects API keys and database credentials from being exposed.


PROJECT IMPACT HIGHLIGHTS
-------------------------
1. Efficiency: Reduced exam creation time from 4 hours to 30 seconds.
2. Scalability: Microservice architecture allows the AI engine to be upgraded independently.
3. Real-time Integrity: Live monitoring tracks student "Active/Inactive" status via Socket.io.
4. Smart Insights: Provides a "Path to Improvement" for students, not just a raw score.
